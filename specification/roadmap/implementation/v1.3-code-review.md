## 1. 🟠 MEDIUM — the interims never leave the server

**Anchor:** `server/roboface_server/orchestrator.py` — `ListeningTurn.drain_partials`, which nothing
calls; `router.py`, which imports `Asr` and not `AsrPartial`.

**Failure scenario.** The tracker computes a partial on every recognition chunk and pushes it onto
`self._partials`. Nothing ever drains it. So:

- **The device never receives `asr_partial`.** RF-044 added the frame, RF-046 taught the firmware to
  render it, and the roadmap lists "interims out as `asr_partial`" as a task. All of that works and
  none of it is reachable, because the one line that forwards them was never written. A feature can
  be complete at both ends and absent in the middle.
- **The queue grows for the length of the utterance.** Deepgram emits interims continuously; a
  thirty-second utterance accumulates hundreds of strings that are never read. Bounded by the
  utterance cap and released when the turn ends, which is why this is MEDIUM — but it is memory held
  for no purpose at all, which is worse than memory held for a bad one.

The two are the same omission, and the second is what makes it more than cosmetic.

**Fix.** Drain the partials where audio is pushed — that is the only point that runs repeatedly
during a window — and send each as an `asr_partial` frame.

## 2. 🟡 LOW — a `listen_start` during a reply waits rather than being refused

`_stream_reply` is awaited inside the dispatch, so a `listen_start` arriving mid-reply is not
processed concurrently; it waits for the reply to finish and then opens normally. That is safe, but
it means a person who interrupts gets their window *after* the character finishes talking rather
than being told the device was busy.

Barge-in is v3.4's, and this is the shape it will have to change. **DEFER → v1.4**, where VAD makes
overlapping windows common enough to matter.

## 3. 🟡 LOW — the ASR budget conflates slow and silent

`ListeningTurn.finish` raises `asr_failed` when nothing resolves within the budget. A vendor that is
merely slow and a vendor that heard nothing at all produce the same error, and the second is not a
failure — it is silence, which the tracker already handles correctly when the stream ends cleanly.

In practice the `UtteranceEnd` backstop resolves both, so the budget is a second line of defence and
rarely reached. **DEFER → v1.4**, alongside the VAD work that will produce far more empty windows.

## What's solid

- **The seam encodes the latency decision.** `open() -> ASRSession` with concurrent push and read
  means no implementation can quietly reintroduce batch recognition; a `transcribe()` shape would
  have made the mistake available.
- **The phrase-hold is tested as sequences.** Thirteen tests that are event orders rather than
  values, because "has this thought finished" is not a property of any single event.
- **The URL builder is separately testable**, and one of its tests asserts the backstop is longer
  than the endpoint — a relationship that is invisible in either number alone and silently wrong if
  inverted.
- **Three latency numbers, logged separately.** The DoD is a claim about which leg is smallest; a
  single total could neither support nor refute it.

## Fixes applied

### Fix 1 — the interims are forwarded

Partials are drained where audio is pushed — the only point that runs repeatedly during a window —
and sent as `asr_partial`. Two regression tests: one asserts the frames reach the device, the other
that the session is released so the queue cannot outlive the turn.

**Verification.** 489 pytest · ruff clean · strict mypy clean.

**Architecture impact.** None to any contract, but a note worth carrying: the frame existed, the
firmware rendered it, and nothing sent it. **A feature can be complete at both ends and absent in
the middle**, and neither end's tests notice. v1.4 adds `vad` frames with the same three-part shape.
