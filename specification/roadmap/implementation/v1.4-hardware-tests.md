# v1.4 — тести на платі

Мета: підібрати пороги активного слухання **вимірюванням, а не підбором**, і перевірити, що
hands-free працює.

Кожен тест — окрема команда, щоб ви були біля пристрою тоді, коли вам зручно. Скрипт сам відлічує
час і сам подає команди платі. Усе, що надрукувала плата, дописується в `hw-test.log`.

```bash
cd ~/development/roboface
./tools/hw-tests.sh          # список тестів
./tools/hw-tests.sh 1        # один тест
```

**Перед першим запуском:** закрийте інші вікна `board.py`. Послідовний порт тримає лише один
процес — інакше плата не відповість, і це виглядатиме як несправність, хоча нею не буде.

---

## Тести 1–3: калібрування

Три вимірювання одним інструментом (`/cal`). Він рахує по кожному 20-мілісекундному кадру дві
величини — пікову гучність і кількість переходів через нуль — і друкує їх розподіл:

```
[cal] кадрів=500 · peak p10=8% p50=10% p90=14% max=22% · zc max=83
```

`p90 = 14%` означає: дев'ять кадрів із десяти тихіші за 14 % від повної шкали. Саме p90 порівнюємо
між тишею і голосом, бо поодинокий грюкіт дверима не має рухати поріг.

### Тест 1 — рівень кімнати

```bash
./tools/hw-tests.sh 1
```

| | |
|---|---|
| **Що робити** | нічого, 10 секунд тиші — кімната як зазвичай |
| **Чого чекати** | рядок `[cal]` з чотирма відсотками |
| **Що це дає** | шум, який VAD **не має** приймати за мову; поріг має бути **вище** цього `p90` |

### Тест 2 — звичайний голос

```bash
./tools/hw-tests.sh 2
```

| | |
|---|---|
| **Що робити** | говорити безперервно 10 с, звичайним голосом, зі звичайної відстані |
| **Чого чекати** | `p90` помітно вище, ніж у тесті 1 |
| **Якщо однаково** | мікрофон не чує голос — жоден поріг не допоможе, беруся за `MIC_GAIN` |

> Говоріть **як зазвичай**, не голосніше. Інакше підберемо поріг, який працює тільки коли кричати.

### Тест 3 — тихий голос або здалеку

```bash
./tools/hw-tests.sh 3
```

| | |
|---|---|
| **Що робити** | те саме, але тихіше або відсунувшись — найгірший випадок, який ще має працювати |
| **Чого чекати** | `p90` усе ще вище, ніж у тесті 1 |
| **Що це дає** | нижня межа, під яку поріг опускати не можна |

**Після тестів 1–3 скажіть, що готово** — лог я прочитаю сам. Візьму поріг посередині між `p90`
тиші та `p90` тихої мови, зашию в прошивку і залию. Це буде число, а не здогад.

Робити паузу тут варто: якщо зазору між тишею і тихим голосом не виявиться, підбирати поріг узагалі
немає сенсу, і тести 4–6 будуть змарнованим часом.

## Тести 4–6: перевірка

### Тест 4 — hands-free оберт

```bash
./tools/hw-tests.sh 4
```

| | |
|---|---|
| **Що робити** | нічого не натискати; сказати одну фразу українською і замовкнути |
| **Чого чекати** | `[state] listening` → `[heard] ваша фраза` → `thinking` → `replying` → `idle` |
| **Після тесту** | скрипт спитає, чи чули ви відповідь уголос, і запише відповідь у лог |

### Тест 5 — хибні спрацювання

```bash
./tools/hw-tests.sh 5
```

| | |
|---|---|
| **Що робити** | нічого, 30 секунд тиші |
| **Чого чекати** | жодного `[state] listening` |
| **Якщо відкривається** | поріг замалий — підніму за числами з тесту 1 |

### Тест 6 — утримання екрана (запасний шлях)

```bash
./tools/hw-tests.sh 6
```

| | |
|---|---|
| **Що робити** | притиснути й тримати екран ~3 с, сказати фразу, відпустити |
| **Чого чекати** | `[listen] … sent N frames`, де **N ≈ 50 на кожну секунду** утримання (~150 за 3 с) |
| **Навіщо** | цей шлях працював завжди; якщо зламався — проблема не в VAD |
| **Після тесту** | те саме питання про звук, і теж у лог |

## Що надіслати

Нічого не надсилати — просто скажіть, що закінчили. Лог я прочитаю сам.

Єдине, чого плата про себе не знає, — **чи пролунала відповідь уголос**. Тому після тестів 4 і 6
скрипт питає про це прямо і кладе вашу відповідь у той самий лог:

```
  Чи почули ви відповідь УГОЛОС із динаміка плати?
    1) так, чув(ла)
    2) ні, тиша
    3) щось було, але нерозбірливо / обірвано
```

У лозі це осідає рядком `[людина] тест 4 · звук: …`, тож переказувати окремо не треба.

## Чому саме так, а не як було

Пороги — це рівно ті дві величини, які друкує `/cal`. Доти я ставив їх навмання: 6 % ловило шум,
25 % не чуло голос, 40 % знову ловило шум — і кожна спроба коштувала перепрошивки й чужого часу.
Три вимірювання дають відповідь один раз.

Окремо варто знати про одну знайдену ваду, бо вона пояснює, чому раніше «нічого не працювало»:
після звільнення динаміка шина I2S лишалась налаштованою на вихід, і `M5.Mic.begin()` рапортував
успіх, не чуючи нічого. Кадри йшли з правильною частотою, рівень виглядав правдоподібно, а людина,
що кричала за 20 см від мікрофона, вимірювалась так само, як порожня кімната. Лікується паузою
20 мс перед стартом мікрофона.
