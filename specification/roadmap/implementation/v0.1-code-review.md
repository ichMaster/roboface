## Findings

### 1. 🟠 MEDIUM — Inbound text frames have no application-level size cap

**Where:** [protocol.py `decode_envelope`](../../../server/roboface_server/protocol.py)

**Failure scenario.** Anything that can reach the WS port — the port binds `0.0.0.0` by design,
because the device connects across the LAN — sends `{"type":"text_in","text":"<50 MB>"}`. The server
decodes it into memory, the echo responder returns it, and `encode` allocates it again on the way
out. Repeat on a few connections and the server is out of memory. There is no authentication in v0.1
(the `unauthorized` code exists but nothing issues it), so "only our device talks to it" is a
statement about the network, not about the server.

`grep -rn "MAX_\|max_size" server/` returns only the port-range constants. The only bound in play is
uvicorn's transport-level `ws_max_size`, which defaults to **16 MiB** — three orders of magnitude
above anything a Core S3 sends over a serial-debug line, not stated anywhere as a contract, and not
applied at all on the ASGI test path.

**Severity note.** MEDIUM *for v0.1*, where the only text frame is a debug line. It becomes HIGH the
moment v1 streams audio and v3 streams JPEG, because then the device legitimately sends large
payloads and "large" stops being obviously wrong.

**Proposed fix.** A `MAX_TEXT_FRAME_BYTES` constant in `protocol.py`, enforced in `decode_envelope`
**before** `json.loads` — the point is not to parse the blob. This is a seam change, so it lands with
its ARCHITECTURE §Contracts note and its contract test in the same commit.

### 2. 🟠 MEDIUM — `log()` fields silently overwrite the identity keys

**Where:** [logging.py `JsonFormatter.format`](../../../server/roboface_server/logging.py) —
`payload.update(fields)` runs *after* the base keys are set.

**Reproduced:**

```python
with connection_context("real-session"):
    log("spoofed", device_id="ATTACKER", session_id="ATTACKER")
# {"ts": ..., "level": "info", "event": "spoofed",
#  "device_id": "ATTACKER", "session_id": "ATTACKER"}
```

**Failure scenario.** One call site anywhere in the server — now or in v4's memory code — passes a
field that happens to be named `device_id`, `session_id`, `event`, `level` or `ts`, and that line is
attributed to the wrong device with no trace that a substitution happened. The whole justification
for this module is that those two keys can be trusted when reading an interleaved multi-device log;
a field that can quietly replace them removes the guarantee without removing the appearance of it.

**Proposed fix.** Write the base keys **last**, so identity always wins, and re-key a colliding
caller field as `field_<name>` rather than dropping it. Not a raise: see finding 3 — logging must
never be able to break a turn.

### 3. 🟠 MEDIUM — A bad `level` string raises out of `log()` and kills the connection

**Where:** [logging.py `log`](../../../server/roboface_server/logging.py) — `LEVELS[level]`.

**Reproduced:** `log("typo", level="warn")` → `KeyError: 'warn'`.

**Failure scenario.** `log()` is called from inside `Router._handle`. A `KeyError` there propagates
out of `serve()`, past the `finally` (so the registry is at least cleaned up), and takes the
connection down. A **typo in a log line** — `"warn"` for `"warning"`, the single most likely such
typo — therefore drops a live device mid-turn, and does so only on the code path that logs it, which
is typically an error path that is rarely exercised. Observability must not be able to cause an
outage.

**Proposed fix.** `LEVELS.get(level, logging.INFO)` in `log()`, with an `unknown_log_level` field
recording the bad value so the typo is still visible. `configure()` stays strict — that is startup
configuration, where failing loudly is right, and `config.py` already validates
`ROBOFACE_LOG_LEVEL` against the same set.

### 4. 🟠 MEDIUM — `DEFAULT_TIMEOUT_S` is declared and never used

**Where:** [tests/fake_device.py](../../../tests/fake_device.py) — the constant is defined with the
docstring *"How long a receive waits before the test is declared hung"*, and nothing reads it.
Confirmed: the name does not appear anywhere after its definition.

**Failure scenario.** A regression stops the server replying — a dispatch branch returns without
sending, a future orchestrator awaits something that never resolves. `FakeDevice.recv()` calls
`WebSocketTestSession.receive_text()`, which blocks on a queue with no timeout. CI does not fail; it
**hangs** until the job's own wall-clock limit kills it, with no failing test to point at. `recv_until`'s
`limit` bounds how many frames are skipped, not how long the first one is waited for.

The constant is worse than its absence: it documents a guarantee the harness does not provide.

**Proposed fix.** Delete the constant, and put a real bound at the level that can enforce one — a
suite-wide `pytest-timeout` so a hang becomes a failing test with a traceback at the blocked line.

### 5. 🟡 LOW — A connection can sit in `awaiting_hello` indefinitely — DEFER → v1.x

`Router._handle_greeting` answers a pre-`hello` frame with an `error` and stays in
`awaiting_hello`. A client may loop forever, holding a connection and a registry slot, answered every
time. Deliberately lenient in v0.1 (a device that mis-orders one frame should be able to recover),
and the right fix — a greeting deadline plus a connection cap — is a connection-lifecycle policy
that wants real traffic to calibrate against. Defer to v1, where the device is actually on the wire.

### 6. 🟡 LOW — `FRAME_TYPES[type(frame)]` raises `KeyError` for an unregistered frame — DEFER → cleanup

`encode` and `_is_from_device` both index `FRAME_TYPES` directly. A frame dataclass added to the
`Frame` union but not to the table fails at runtime rather than at type-check time. Not reachable
today (the union and the table are written together and the codec tests cover every member), but it
is a trap for v0.2, which adds frames. A `Final` exhaustiveness assertion at import, or a `ClassVar`
on each frame, removes the class of bug — small, but it is refactoring rather than a defect.

### 7. 🟡 LOW — `create_app()` does not configure logging — DEFER → deployment story

`configure()` is called only from `main()`. A deployment that runs `uvicorn
roboface_server.app:create_app --factory` — the idiomatic invocation for a factory — gets a
`roboface` logger with no handler, so lines propagate to root and come out as unformatted text
rather than JSON. Not a defect today: nothing documents that invocation, and `main()` is the
entrypoint. It becomes one the day someone writes a Dockerfile. Fixing it inside `create_app()` would
also reorder handler installation against the test fixtures, so it wants doing deliberately.

### 8. 🟡 LOW — `WebSocketTransport.receive()` maps any `RuntimeError` to `Disconnected` — DEFER → cleanup

The `except (WebSocketDisconnect, RuntimeError)` is there because Starlette raises a bare
`RuntimeError` for "receive after close". It also swallows any *other* `RuntimeError` raised inside
the ASGI receive path, reporting a genuine framework fault as a clean client disconnect. Narrowing it
means matching on the message text, which is its own fragility; worth revisiting when the v1 audio
path exercises this code far harder.

### 9. ⚪ SPEC — `ErrorCode` has no code for an unparseable inbound frame — DEFER → **decision needed**

Carried forward from the v0.1 execution report. `ErrorCode` enumerates eleven values and none of them
means "the device sent something this server cannot parse". Malformed frames, unknown message types
and declared-but-unimplemented types are therefore all reported as `internal`, which tells the device
the *server* failed when the device's own frame was at fault — and, from v0.4, renders the error face
for a fault the device caused.

This is not a code fix. Adding a twelfth code (`bad_frame`) changes a contract the specification
enumerates explicitly, and that is the user's call, not the reviewer's. **Recommended:** add
`bad_frame` to ARCHITECTURE §Error codes and to the contract test in v0.2, where the error-mapping
work is already scheduled (`llm_timeout` / `llm_failed` / `rate_limited`). Flagged rather than done.

## What's solid

- **The pure/glue split holds.** `protocol.py` imports no framework, and that is asserted in a
  *fresh subprocess* rather than against a `sys.modules` already polluted by the rest of the suite.
  The router is written against a small transport protocol, which is why teardown could be tested on
  all three paths — including the exception path, which a real socket cannot be made to produce on
  demand.
- **`UnsupportedMessage` vs `UnknownMessage`** is the right distinction and it is already paying:
  the router answers a declared-but-unbuilt type cleanly and treats an invented one as a broken
  device, and v0.2 extends the codec by adding a decoder rather than by touching the envelope.
- **The `Responder` seam is honestly minimal.** One method, no provider package, no streaming
  scaffolding built ahead of its phase. v0.2 attaches at exactly one point.
- **The fake device earned its place immediately**, surfacing the double-close defect that every
  rejected `hello` would have hit in production and that the unit tests structurally could not see.
- **Secrets discipline is clean.** No `.env` value is read outside `config.py`, none is logged, and
  the body-redaction rule is asserted end-to-end against a card-number-shaped payload rather than
  only against the helper.
