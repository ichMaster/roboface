## 1. 🟠 MEDIUM — the uplink can change microphone in the middle of a word

**Where:** `firmware/src/pure/stereo.h` — `chooseSource`, and its caller in `audio_io.cpp::tick`.

**Failure scenario.** The choice is made fresh from every 20 ms frame, with a hard threshold and
nothing holding it:

1. A hand rests near — not over — one microphone, or a speaker turns their head. The quieter
   channel's ratio hovers around `kObstructedChannelRatio` (0.20).
2. Frame *n* reads 0.19 → the mix switches to one channel. Frame *n+1* reads 0.21 → back to the
   average. Frame *n+2* → back again.
3. The uplink is now alternating between two different signals **fifty times a second**, mid-word.
   Each switch is a step discontinuity: the average and one channel differ in level and in phase,
   so the stream carries a click every 20 ms.
4. ASR sees a word peppered with transients. The DoD for this phase says accuracy in a noisy room
   must be **no worse** than the single-channel baseline; this is a mechanism for making it worse,
   and it is invisible from the device — every level meter and every VAD number looks normal.

**And the same code has no floor.** In genuine near-silence `louder` is a noise floor and `quieter`
is a second, independent noise floor. Their ratio is arbitrary, so a silent room can pick a channel
for no reason — and then the *first frame of speech* arrives on whichever channel silence happened
to select.

**Measured on hardware, and the measurement is why this is MEDIUM rather than HIGH.** A desk in a
quiet room reads `left=0.0425 right=0.0392`, a ratio of 0.92 — nowhere near the threshold, and four
consecutive samples all reported `середнє двох`. The room is loud enough that both microphones agree.
So the bad case needs one microphone deliberately obstructed, which is exactly the case the feature
was written for.

**Why the tests did not catch it.** They test `chooseSource` on single, static level pairs — 0.92 and
0.025 — and both are far from the threshold. Nothing feeds it a *sequence* that crosses the boundary,
which is the only shape in which this defect exists. That is the same gap v2.3's envelope had: the
rule was right and nothing asked what happened when it was applied repeatedly.

**Proposed fix.** Hysteresis, as every other threshold in this project has (`lipsync.h`, `motion.h`,
`proximity.h` all pair an enter and a release threshold), plus a floor below which the question is not
asked at all. The state has to live somewhere, so `chooseSource` becomes a small class rather than a
free function — which is the right shape anyway: it is a decision with memory, like every other
threshold-with-hysteresis here.

**Regression test.** A sequence that walks the ratio across the threshold and back, asserting the
choice changes at most once; and a silent sequence asserting it never leaves `kBoth`.

## 2. 🟠 MEDIUM — the gaze the server was told about is erased by the next frame it sends

**Where:** `server/roboface_server/emotion.py::frame_for` (the `gaze` parameter), and every caller of
it in `router.py` and `orchestrator.py`.

**Failure scenario.**

1. The device reports `voice`/`direction` with `x = -0.6`. `_gaze_from_event` stores it on the
   connection. Correct.
2. The person speaks. The router sends `frame_for(TurnState.LISTENING)` — **without `gaze`**, because
   no caller passes it. The frame carries `gaze: None`.
3. The device's `server_gaze_x_` becomes 0.
4. It does not show, because the device's *local* voice estimate outranks the server's. So the bug
   is invisible for exactly as long as the local estimate is present — and the moment it lapses
   (`kDirectionHoldMs`, 1.5 s after the voice stops) the face returns not to the reported direction
   but to centre.

**The deeper problem is that the parameter has no caller at all.** `grep 'frame_for(' server/ | grep
gaze` returns zero. It was added in RF-075 and wired to nothing — which is the exact smell the v2.4
review raised as finding #3, in the same words: *a method written for a documented situation and
never wired up means either the situation is not real, in which case it should go, or it is real and
unhandled*. Here it is the second, and ARCHITECTURE §Gaze already documents the server's gaze as the
third level of authority, so the situation is real and specified.

**Why the tests did not catch it.** The contract test proves `EmotionFrame.gaze` round-trips, and the
unit tests prove `frame_for` puts a passed gaze into the frame. Both pass. Neither asks whether
anything *passes* one — a test of a function's behaviour cannot notice that it has no callers.

**Proposed fix.** Thread the connection's gaze through the frames sent during a turn. The
orchestrator's frames are the awkward ones — it does not hold the connection — so the honest minimal
fix is at the router's `_send_emotion`, which every frame passes through: attach `conn.gaze` when the
frame does not already carry one. One place, and it cannot be forgotten by a future caller.

**Regression test.** A fake device reports a direction, then runs a turn; every emotion frame it
receives carries the gaze.

## 3. 🟡 LOW — three private Newton loops beside a shared one

**Where:** `pure/envelope.h`, `pure/motion.h`, `pure/stereo.h::channelRms` — each with its own
"start at the value, iterate N times" square root, now that `pure/roots.h` exists.

**Why it is real.** RF-074 found that this pattern silently returns a badly wrong answer for large
inputs, and fixed it in one place. The other three are correct *today* because their inputs are
small — `channelRms` divides by `count` first, `motion.h` works in g, `envelope.h` in normalised
samples. But "correct because nobody has fed it a big number yet" is a property of the callers, not
of the code.

**Why it is deferred rather than fixed now.** Replacing them changes the last bits of values that
lip-sync thresholds, shake detection and the mouth envelope were tuned against, across three phases
of on-hardware calibration. That is a re-tuning exercise disguised as a cleanup, and it belongs in a
deliberate pass with the board in hand — not in the tail of a phase about microphones.

**Home:** a cleanup pass. Recorded here so that the next person to touch one of them knows a
correct shared implementation already exists.

## What's solid

- **The gate issue did its job, and its shape is the lesson from v2.4 applied.** RF-073 was defined
  to end in a number rather than a compile, and the number changed the design twice: the magnitude
  peak became a signed range because "some imbalance happened" does not distinguish two microphones
  from one noisy channel, and the measured ambient coherence (~0.50, not ~0) got written into
  `direction.h` as a stated limit rather than discovered later by someone wondering why a fan moves
  the gaze.
- **The physics is in the header, and it ruled out the obvious approach.** Writing out that 40 mm is
  ±2 samples at 16 kHz is what stopped a cross-correlation lag estimator being built and trusted.
- **`present` as a third state** is carried end to end — `DirectionEstimate.present`, `Gaze | None`,
  and each renderer source skipped rather than contributing a zero. The alternative (centre as the
  default) would have pinned the eyes forward against the idle drift, and would have looked like a
  rendering bug.
- **The bias-not-a-gate test** pins the property at every confidence value rather than at one, which
  is the difference between testing the fix and testing the example.
- **Two bugs were found by writing the comment rather than by running the code** — the observer
  ordering in `audio_io::tick`, and the throttle whose second `return` contradicted its own
  description. Both were caught while explaining what the code did.

# Fixes applied

**Final validation:** `pytest` 729 passed / 3 skipped · `mypy --strict` clean · `ruff` clean ·
`pio test -e native` 438 passed · `pio run -e cores3` compiles and flashes.

## #1 — the choice grew a memory

**The change.** `chooseSource` became `SourceChooser`, with an enter threshold (0.20), a release
threshold (0.35) and a floor (0.004) below which the question is not asked and the previous answer
stands. That is the shape every other threshold in this project already had — `lipsync.h`,
`motion.h` and `proximity.h` all pair an enter and a release — and the free function was wrong
precisely because it had nowhere to keep an answer.

Holding through silence is deliberate and is not the same as resetting to `kBoth`: a pause in the
middle of a sentence must not switch microphones back and forth around each word. The reset happens
once, when a listening window opens, because a microphone obstructed during the last conversation
is not evidence about this one.

**The regression test.** A ratio walking back and forth across 0.20 for sixty frames, asserting the
choice changes **at most once**. The old tests could not have caught this: they fed single static
level pairs, and the defect exists only in a sequence.

**Architecture impact.** None to a contract. Worth recording as a rule the project keeps
rediscovering: **a threshold evaluated repeatedly needs hysteresis, and a threshold with hysteresis
needs somewhere to live.** A free function that makes a decision every 20 ms is a free function that
will oscillate.

## #2 — the gaze is attached where every frame passes

**The change.** `_send_emotion` gained the connection and attaches `conn.gaze` when the frame does
not already carry one. Attaching it at each `frame_for` call site would have been six places to
forget; the orchestrator's frames settle the argument, since it does not hold the connection at all.

A frame that already carries a gaze keeps it — a later phase with a real opinion about where to look
(the vision turn in v3) must outrank a remembered voice.

**The regression test.** `tests/integration/test_voice_direction.py` asserts the *journey*: report a
direction, run a turn, and every emotion frame carries it. Plus the two absences — no report means
`None` rather than a centred stare, and unusable `meta` means `None` rather than 0.0, which matters
because 0.0 is a perfectly valid direction and so the wrong default is indistinguishable from a real
report.

**Architecture impact.** `ARCHITECTURE.md` §Gaze already documented the server's gaze as the third
level of authority. This makes that true; it was documented and unimplemented. The doc needed no
change, which is the good case — but it is worth noting that **a specification can be satisfied by a
test and still be false of the running system**, which is what happened here.
