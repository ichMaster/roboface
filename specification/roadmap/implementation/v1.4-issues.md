# v1.4 — GitHub Issues

Issues for phase **v1.4 — Active listening (VAD)** (version **v1 — Voice**),
derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md) (§v1.4) and the
contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md) (§Turn lifecycle, §Audio, §Interaction,
§Firmware architecture). This file is scoped to a single phase; IDs continue from the previous
phase (RF-047 → **RF-048…RF-053**).

v1.4 removes the finger. The microphone is already open — v1.3 left capture as the resting state of
the shared bus — so what is missing is a decision: *when does a person start talking, and when have
they stopped*. That decision is pure logic with an injected clock, and everything else in this phase
is wiring it to a turn the previous three versions already know how to run. No new wire message is
introduced; the device still sends `listen_start` → `audio` → `listen_stop`, and VAD only decides
when.

## Reconciliation notes (real code, not just the design)

Three things carried out of the earlier reviews and the current implementation, because they change
what these issues may assume:

- **v1.2 review, "Architecture impact":** *the server owns the listening window; the device's hold
  is a request for one.* v1.4 opens windows with no finger involved and **must treat a refusal the
  same way** — a rejected `listen_start` cancels the window rather than streaming into nothing.
- **v1.3 review predicted a `vad` wire frame.** There is none in `protocol.py` and none in
  `ARCHITECTURE.md`, and §v1.4's Tasks do not ask for one. The device reports *audio*, and the
  server decides; a frame announcing "I think this is speech" would be the device asserting a
  judgement the server does not consume. **Not added** — recorded here so the next reconciliation
  does not read its absence as an oversight.
- **Capture is already always-on.** v1.3's fix made input the resting state of the shared I2S bus
  (`AudioIo::enterMicMode`), and `stopListening` no longer tears the codec down. v1.4 therefore
  changes *what is streamed*, not *what is recording* — an important distinction for the
  half-duplex guard, which must stop the uplink without stopping the microphone.

## v1.4 — Active listening (VAD)

### RF-048 — The VAD endpointer, as pure logic

**Description:**
The decision at the heart of the phase: from a stream of 20 ms frames, when did speech start and
when did it end. Header-only in `firmware/src/pure/`, `namespace roboface`, Arduino-free and driven
by an injected clock — the same discipline `pure/ptt.h` follows, and for the same reason: these
rules are almost entirely about time, and time is the one thing a device test cannot rush.

**What needs to be done:**
- Add `firmware/src/pure/vad.h` — an endpointer fed one frame's energy at a time, returning
  **transitions** (`kNone` / `kSpeechStarted` / `kSpeechEnded` / `kDiscarded`), never levels. A
  caller polling a boolean would keep the same state in a second place, and the two would
  eventually disagree (`pure/ptt.h` states this rule; follow it).
- Energy plus zero-crossing rate, so a steady low-frequency rumble is not mistaken for a voice —
  the v1.3 review recorded captures whose energy sat entirely below 100 Hz and carried no speech.
- Configurable: **sensitivity** (the speech threshold), **minimum speech** (below which the
  utterance is discarded rather than ended), **end-pause** (silence before the utterance closes),
  and **pre-roll** (how much audio before the trigger must be kept).
- A hangover so a plosive gap mid-word does not end an utterance.
- Reuse `roboface::peakLevel` / `samplesForMs` from `pure/level.h` and `pure/capture.h` rather than
  re-deriving frame arithmetic.

**Dependencies:** None

**Expected result:**
A host-testable endpointer that turns a sequence of frames into exactly one speech-start and one
speech-end per utterance, with sub-minimum utterances reported as discarded.

**Acceptance criteria:**
- [ ] Transitions are reported once each per utterance, never repeated while the condition holds.
- [ ] **Unit test:** against generated PCM fixtures — continuous speech, silence, a short noise
      burst, and speech with a long mid-utterance pause — deterministic with an injected clock.
- [ ] A frame sequence below the minimum-speech duration yields `kDiscarded` and no start/end pair.
- [ ] Compiles under `pio test -e native`; no `M5`/`Arduino`/`WiFi` include reaches it.
- [ ] Ties to §v1.4 Tests: "host — the endpointer against recorded PCM fixtures … deterministic
      with an injected clock".

### RF-049 — Active listening: pre-roll, and a window opened without a finger

**Description:**
Wire RF-048 to the turn state machine in `firmware/src/app/` and `main.cpp`. The microphone is
already always recording (v1.3), so this issue decides when its frames go *up the link*: speech
start opens the window and the pre-roll is flushed first, so the first syllable is never lost.

**What needs to be done:**
- A pre-roll ring in `AudioIo` holding the last N ms of frames while idle; on speech start, send
  `listen_start` and then flush the ring before live frames.
- Drive the existing `beginListening()` / `stopListening()` from the endpointer instead of only
  from `PushToTalk`, keeping both paths on one code path so they cannot diverge.
- The local end-pause sends `listen_stop` — the backstop for when the link or the recogniser is
  unavailable (§v1.4: "with the local end-pause as the backstop").
- **A refused window is not a window.** Per the v1.2 review's architecture note, if the server
  rejects `listen_start` the device abandons the utterance and returns to idle rather than
  streaming audio nobody asked for.
- Keep the turn state machine authoritative: no new device state, `kListening` as it already is.

**Dependencies:** RF-048

**Expected result:**
Speaking into the room opens the uplink with the first syllable intact and closes it after the
end-pause, with no touch involved.

**Acceptance criteria:**
- [ ] `listen_start` is sent exactly once per utterance, followed by pre-roll then live frames.
- [ ] **Unit test:** the pre-roll ring keeps exactly the configured duration and flushes in order
      (pure logic, host-tested).
- [ ] A rejected `listen_start` abandons the utterance and leaves the device idle.
- [ ] Touch-and-hold still opens a window through the same path.
- [ ] Ties to §v1.4 DoD: "speaking into the room starts and ends a turn with no touch".

### RF-050 — Half-duplex: the device must not answer itself

**Description:**
The device's own speaker is the loudest thing in the room, and with an always-open microphone it
would hear itself, trigger, and answer its own reply. Half-duplex until AEC arrives in v3.4
(ARCHITECTURE §Audio).

**What needs to be done:**
- Suspend the **uplink** for the duration of playback and resume after `tts_end` — suspend the
  streaming, not the microphone: capture is the resting state of the shared bus and tearing the
  codec down around every reply is the churn v1.3's review warned about.
- Reset the endpointer when listening resumes, so silence during playback is not counted toward an
  end-pause and the tail of the reply is not counted toward speech.
- Cover the paths where playback ends abnormally — a cancelled turn, a dropped socket — so the
  uplink cannot stay suspended forever and leave the device deaf.

**Dependencies:** RF-049

**Expected result:**
The device never opens a window because of its own voice, and hears the room again as soon as it
stops speaking.

**Acceptance criteria:**
- [ ] No `listen_start` is emitted while playback is in progress.
- [ ] **Unit test:** the guard's state machine — suspend, resume on `tts_end`, and resume on each
      abnormal end — host-tested with an injected clock.
- [ ] Listening resumes after `tts_end` with a cleared endpointer.
- [ ] Ties to §v1.4 DoD: "the device does not trigger on its own speech".

### RF-051 — Sensitivity, end-pause, and the switch back to PTT

**Description:**
The endpointer's constants are the ones most likely to need a different value in a different room,
and the phase explicitly requires an off switch that falls back to touch-only.

**What needs to be done:**
- `sensitivity`, `end_pause_ms` and `active_listening` in `firmware/src/config.example.h` with
  documented defaults, mirrored into the gitignored `config.h`.
- Serial commands to change them at runtime and read them back — a value that needs a reflash to
  compare cannot be tuned, because the reboot changes the room and the speaker along with it.
- With active listening **off**, the device is PTT-only and behaves exactly as v1.3 did.
- Report the setting in the existing status line so the current mode is never a guess.

**Dependencies:** RF-049

**Expected result:**
Active listening can be tuned without a reflash and turned off entirely, leaving v1.3's behaviour.

**Acceptance criteria:**
- [ ] Defaults live in `config.example.h`; `config.h` stays gitignored (it holds the WiFi password).
- [ ] **Unit test:** the settings carrier and its bounds-checking are pure and host-tested; an
      out-of-range value is refused rather than silently clamped into nonsense.
- [ ] With the switch off, no VAD-driven `listen_start` is ever emitted and PTT still works.
- [ ] Ties to §v1.4 Tasks: "Config: sensitivity, end-pause, and an on/off switch".

### RF-052 — The recogniser's endpointing closes the utterance

**Description:**
§v1.4 makes the **server's** endpointing the primary end-of-utterance signal, with the device's
end-pause only as the backstop. The recogniser already decides this — v1.3 configured Deepgram's
`endpointing` and `utterance_end_ms` — but the server currently resolves the transcript only when
the device says `listen_stop`. This issue makes the server act on the decision it already receives.
Touches `server/roboface_server/` (router, orchestrator) and `specification/ARCHITECTURE.md`.

**What needs to be done:**
- When the recogniser reports a final utterance mid-window, resolve the turn and send `asr` without
  waiting for `listen_stop`.
- The device closes its window on `asr`, so the two ends agree on which utterance ended; a
  `listen_stop` that arrives afterwards is idempotent, not a second turn.
- Honour v1.3's phrase-hold: an un-punctuated `speech_final` is held for the continuation or the
  backstop, so the character never answers half a phrase.
- **This changes the documented turn lifecycle**, so it carries its `ARCHITECTURE.md` update and
  contract test in this same commit.

**Dependencies:** RF-049

**Expected result:**
An utterance ends when the recogniser says it ended, and the device's end-pause is only needed when
the server cannot say.

**Acceptance criteria:**
- [ ] **Contract test:** the turn lifecycle — recogniser-final closes the utterance, and a later
      `listen_stop` does not open a second turn — pinned as a wire-level test.
- [ ] `specification/ARCHITECTURE.md` §Turn lifecycle updated in the same commit.
- [ ] **Unit test:** the hold for an un-punctuated final still applies on this path, with the ASR
      provider mocked (no paid API).
- [ ] Ties to §v1.4: "the utterance ends on the server's endpointing decision".

### RF-053 — Hands-free end to end, and the false trigger that never becomes a turn

**Description:**
The phase's closing integration: a fake device drives VAD-marked utterances through a full turn, and
a burst too short to be speech is discarded without any turn existing at all. Touches `tests/`.

**What needs to be done:**
- Integration test: a fake device streams a VAD-marked utterance and receives a complete turn —
  `listen_start` → `audio` → resolution → `reply`, with every provider mocked.
- A sub-minimum utterance produces **no** `listen_start`/`listen_stop` pair and no turn — the
  device discards it rather than making the server special-case an empty transcript, which is the
  rule `pure/ptt.h` already applies to a tap.
- Half-duplex proven across a turn: no window opens while the reply plays.
- Record the DoD result and the measured behaviour in the execution report.

**Dependencies:** RF-050, RF-051, RF-052

**Expected result:**
v1 is a complete hands-free voice companion: speak, be answered, with no touch and no false turns.

**Acceptance criteria:**
- [ ] **Integration test:** a fake device driving a VAD-marked utterance through a full turn, all
      providers mocked and the suite deterministic.
- [ ] A short noise burst yields no turn and no protocol traffic.
- [ ] The backup PTT still opens a window with active listening on.
- [ ] Ties to §v1.4 DoD in full: hands-free start and end, no self-triggering, PTT intact.

## v1.4 scope notes

**Total effort:** ~12 points (2 S, 4 M) — roughly two weeks of the sizes above.
**Critical path:** RF-048 → RF-049 → RF-052 → RF-053.
**Phase DoD (roadmap §v1.4):** speaking into the room starts and ends a turn with no touch; the
device does not trigger on its own speech; the backup PTT still works; v1 is a complete hands-free
voice companion.
**Contracts pinned this phase:** the **turn lifecycle** (RF-052 — recogniser-final closes the
utterance, `ARCHITECTURE.md` + contract test in the same commit). No new wire message: the device
still sends `listen_start` / `audio` / `listen_stop`, and the reconciliation note above records why
the predicted `vad` frame was not added.
**Model note:** chat runs on **Gemini 2.5 Flash only** (`thinkingBudget: 0`) behind the
`LLMProvider` seam; **no paid APIs** — every provider seam is mocked and a fake device drives the
protocol for unit + integration tests.
**Carried into this phase from earlier reviews:** the server owns the listening window (v1.2); a
feature can be complete at both ends and absent in the middle (v1.3); capture is already always-on,
so the half-duplex guard stops the uplink, not the microphone (v1.3).
**Still held, and larger than it looks:** PSRAM reports `found=1 size=0`, leaving ~53 KB of internal
RAM once the sprite and the audio backlog are placed — which is what makes `i2s_alloc_dma_buffer`
fail during a mic/speaker switch. RF-050's guard touches exactly that switch. Homed to the v1 HARDEN
sweep.
