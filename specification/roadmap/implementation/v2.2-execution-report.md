## Detailed Results

### RF-059: The `EmotionFrame` contract and the emotion enum
**Status:** completed · **Commit:** `d68d17e`
**Validation:** [x] contract test · [x] unit tests · [x] mypy · [x] ARCHITECTURE

`emotion{}` is the one frame whose decoder **coerces rather than raising**, and that asymmetry is
the issue's real content. Two reasons, both load-bearing: a face is not worth dropping a connection
over — the reply is still arriving on the same socket — and the two tiers are separately
releasable, so neither may assume the other sanitised what it sent. Every coercion logs once at
debug, because a model that keeps reporting `"happy"` is a **prompt** bug and that line is the only
way anyone would ever find it.

Two existing codec tests asserted `emotion` was declared-but-unimplemented. They moved to
`config_updated` and `event`; a type leaving that list is what a phase landing looks like from the
codec's side.

### RF-060: The emotion engine
**Status:** completed · **Commit:** `44c70f3`
**Validation:** [x] unit tests (29) · [x] mypy · [x] totality over both enums

Three tables, each total over its key and each carrying its reasoning. The `ttl_ms` numbers are the
part worth re-reading: they are a **liveness guarantee, not a schedule**. In normal operation none
ever expires, because a frame is sent on every state change; what they bound is a connection dying
between two of them. So each is "longer than this state can legitimately last" — `listening`
outlives the longest utterance the protocol allows, and `replying` is the longest of all, because
the device is still playing audio the server finished sending.

Gaze stays absent rather than centred. "No opinion" and "look straight ahead" are different
instructions once a device reflex can override one of them.

### RF-061: Structured output from Gemini
**Status:** completed · **Commit:** `f3f2f76`
**Validation:** [x] contract test (seam) · [x] unit tests (59 for the reader alone) · [x] mypy

The phase's largest risk, and it landed on the predicted line. Two decisions carried it:

**The schema's field order is the design.** `emotion` and `intensity` are declared before `reply`
with `property_ordering` pinned, so the report is complete in the model's first chunk. A schema with
`reply` first would stream the whole answer before the server learned how the model felt — the same
latency mistake as a second API call, spelled differently.

**The JSON is read as it arrives.** `jsonstream.py` hands scalars over the moment they close and
streams the reply's contents in pieces. Collecting the response and calling `json.loads` would have
cost the entire generation time before the first word: structured output would have become a latency
regression, which is the obvious way to get this phase wrong.

One design error was caught by writing the tests rather than by review: the reader first emitted a
`TextDelta` **per character**, which is correct and unusable — each becomes a `reply` frame, so a
400-character answer would be 400 websocket frames instead of the dozen the network delivered. Text
is now batched per chunk, which delays nothing because the chunk is the unit the text arrived in.

### RF-062: The server emits `emotion{}`
**Status:** completed · **Commit:** `7d42fe5`
**Validation:** [x] integration tests (15) · [x] contract tests (3, turn lifecycle) · [x] mypy

Two orderings are the substance and both are pinned: the `replying` frame precedes the first delta,
and the relax-to-neutral precedes `reply{final: true}` (which is the turn's end marker — a device
may stop reading there, so a frame after it may never be looked at).

**A real defect surfaced here**, found by the abandonment tests rather than by review: the
`thinking` yield sat outside `_run_turn`'s `try`, so a consumer walking away at the turn's very
first event skipped the rollback and left the user message stranded in history. A generator
abandoned before it enters a `try` never runs the `finally`. The "a turn has exactly two endings"
invariant, closed in v0.2, had silently regained a third.

### RF-063: The device renders the frame it is given
**Status:** completed · **Commit:** `b88c59e`
**Validation:** [x] contract test · [x] host tests (293 total, 23 new) · [x] compiles · [ ] hardware

Two decisions moved into `pure/facehold.h` rather than staying in the renderer, because both are
decisions and neither is drawing. `FaceHold` reports ttl expiry as an **edge** — a level would
re-target the crossfade on every subsequent frame and the face would never finish relaxing.
`mouthRuns(server_permits, speaker_playing)` is the v2.1.2 rule written down and given a regression
test named after the bug.

## Architecture impact

Four of the five pinned seams moved in this phase, each with its `ARCHITECTURE.md` update and its
contract test in the same commit:

| Seam | Change |
|---|---|
| **WS protocol** | `emotion{}` implemented; the only frame whose decoder coerces rather than raising |
| **`EmotionFrame`** | field-for-field agreement documented, plus the coercion rules, `#rrggbb` rather than "hex", omitted gaze as "no opinion" |
| **`LLMProvider`** | `stream` yields `ReplyText \| ModelReport`; order is part of the contract |
| **`IFaceRenderer`** | gained `show(const EmotionFrame&)`; the `DeviceState` overload stays as the authority rule |

One rule is now stated in three places because it has already been got wrong once: **`speaking` is
a permission, not a duration.** ARCHITECTURE §EmotionFrame says it, `mouthRuns` enforces it, and
`test_facehold.cpp` holds it still.

## Deferred: every by-hand check

Nothing was verified on the board during this phase, by decision rather than by omission.

The reason is worth recording, because it cost real time to find. The board's `config.h` points at
**192.168.1.197**, which turned out to be a **different live machine on the LAN** rather than the
development host. It had been answering the board with genuine Gemini replies throughout, so the
absent `emotion{}` frames looked like a device-side bug — the parser, the dispatch and the binary
were all checked before the address was. The device code was correct the whole time.

The project owner's decision, recorded here so the next phase inherits it rather than rediscovering
it: **the server is verified from 192.168.1.197**, and every by-hand check is deferred to the end of
code generation and collected into one manual-test document with its scripts.
