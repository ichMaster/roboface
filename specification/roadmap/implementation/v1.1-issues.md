# v1.1 — GitHub Issues

Issues for phase **v1.1 — Streaming TTS playback** (version **v1 — Voice**),
derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md) (§v1.1) and the
contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md) (§Contracts, §Audio pipeline, §Turn lifecycle,
§Budgets and abort semantics).
This file is scoped to a single phase; IDs continue from the previous phase
(RF-027 → **RF-028…RF-034**).

This is where the pipeline stops being request/response: the mouth opens before the sentence exists.
A completed clause goes to TTS while the model is still generating the rest, and its audio reaches
the device while later words are still being written.

**Reconciled against the real code, and it is further along than the roadmap assumes.** v0.1 fixed
the whole wire vocabulary up front: `ServerMessage.TTS_AUDIO`, `ServerMessage.TTS_END` and
`ErrorCode.TTS_FAILED` are already declared and already mirrored in `firmware/src/pure/ws_protocol.h`,
and `server_binary_meaning(BinaryPhase.SPEAKING) → TTS_AUDIO` already gives an unlabelled binary
frame its meaning. So no message type is invented here. **What is genuinely missing is narrower and
more specific:** `Transport.send()` accepts only `str`, so there is no way to put bytes on the wire
at all — that is the seam this phase has to open.

## v1.1 — Streaming TTS playback

### RF-028 — `sentence.py` — the `PhraseSplitter`

**Description:**
The pure text logic that decides when a phrase is finished enough to speak. Touches
`server/roboface_server/sentence.py` and `tests/unit/` only — no I/O, no provider, no protocol.

**What needs to be done:**
- `PhraseSplitter`: `feed(delta) -> list[str]` and `flush() -> str | None`, consuming LLM deltas and
  emitting complete phrases as they close.
- A phrase closes at a sentence boundary (`.` `!` `?` `…`) or a clause boundary (`;`) **only when the
  boundary is followed by whitespace**. Two failures this prevents, both of which produce audible
  nonsense: `3.5` would otherwise split into "three point" and "five", and a boundary sitting at the
  very end of the buffer would be spoken before the next delta reveals it was a decimal point.
- Skip Ukrainian abbreviations — `напр.`, `т.д.`, `т.п.`, `вул.`, `ін.`, `рр.`, `ст.` — which end in
  a period that is not a sentence end.
- Force-flush a runaway clause at `max_chars`, **on a word boundary**, so a model that never
  punctuates still speaks instead of buffering silently to the end of the turn.
- `flush()` returns the tail, so a short reply with no terminal punctuation is still spoken.
- Deltas split a boundary character from its following whitespace: the splitter is fed
  character-by-character in the tests because that is what a real stream does.

**Dependencies:** None

**Expected result:**
A pure splitter that turns a stream of deltas into speakable phrases, proven against a fixture set
without any provider.

**Acceptance criteria:**
- [ ] A boundary not followed by whitespace does not split — `3.5`, `т.д.`, and a period arriving as
      the last character of a delta
- [ ] Abbreviations in the list do not split; the same letters mid-word do not false-positive
- [ ] A runaway clause force-flushes at `max_chars` on a word boundary, never mid-word
- [ ] `flush()` yields the tail; feeding a whole reply then flushing loses no characters
- [ ] **Unit test:** the above, fed delta-by-delta, in `tests/unit/`
- [ ] Ties to the phase DoD: "the first spoken phrase is never a half-word"

### RF-029 — The `TTSProvider` seam and its mock

**Description:**
The second provider seam, alongside `LLMProvider`. Touches
`server/roboface_server/providers/{base,mock}.py`, `specification/ARCHITECTURE.md`, and
`tests/contract/`.

**What needs to be done:**
- `TTSProvider` Protocol in `providers/base.py`: `synthesize(text: str) -> AsyncIterator[bytes]`,
  yielding PCM16 16 kHz mono — the device's playback format, so nothing decodes anywhere.
- Not `async def`: the caller must get the iterator immediately and await chunks one at a time, the
  same shape `LLMProvider.stream` already has and for the same reason.
- A mock that yields **several** chunks, not one: a single-chunk mock would let a consumer that
  accumulates before sending pass every test, and accumulating is precisely what this phase exists
  to avoid.
- `ProviderError` with `ErrorCode.TTS_FAILED` — the code already exists in `protocol.py`.
- **Seam change:** update `specification/ARCHITECTURE.md` §Contracts with the seam, in this issue,
  with its contract test.

**Dependencies:** None

**Expected result:**
A pinned `TTSProvider` seam with a mock the rest of the phase can be built against.

**Acceptance criteria:**
- [ ] `TTSProvider` is a Protocol matching the documented signature; the mock satisfies it
- [ ] The mock yields more than one chunk per call
- [ ] **Contract test:** the seam's shape and that a failure raises `ProviderError` carrying `tts_failed`
- [ ] `specification/ARCHITECTURE.md` records the seam, in this commit
- [ ] **No paid API:** nothing in this issue calls ElevenLabs

### RF-030 — `providers/elevenlabs.py` — streaming PCM16

**Description:**
The real adapter behind the seam. Touches `server/roboface_server/providers/elevenlabs.py`,
`config.py`, and `tests/unit/`.

**What needs to be done:**
- The streaming endpoint (`/v1/text-to-speech/{voice_id}/stream`) with
  `output_format=pcm_16000` — 16 kHz PCM16 straight into the device's playback format, so there is
  no decode step on either side.
- Voice id, model id and output format from config, following `GEMINI_*`'s pattern in `config.py`:
  `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL`, `ELEVENLABS_OUTPUT_FORMAT` are
  already present in `server/.env`.
- Chunks yielded **as they arrive**, never accumulated.
- Imported lazily inside the module, as `providers/gemini.py` is, so the default suite runs without
  the SDK installed.
- Failures mapped to `ProviderError(..., ErrorCode.TTS_FAILED)`. Follow v0.2's review finding on the
  Gemini adapter: hint only the statuses whose meaning is unambiguous, and do **not** map a vendor
  5xx to anything that would blame the device.
- `Settings.__repr__` must keep redacting — `ELEVENLABS_API_KEY` is a secret exactly as
  `GEMINI_API_KEY` is, and v0.2's HIGH finding was that a repr printed one in full.

**Dependencies:** RF-029

**Expected result:**
Text becomes streamed PCM16 through the seam, with the key never printable.

**Acceptance criteria:**
- [ ] Chunks are yielded as received, verified against a fake streaming HTTP response
- [ ] Config is read through `config.py`; a missing key is an enumerated failure, not a traceback
- [ ] `repr(Settings)` redacts `ELEVENLABS_API_KEY` — regression test, per v0.2 finding 1
- [ ] Errors map to `tts_failed` without misattributing a vendor fault to the device
- [ ] **Unit test:** the adapter against a mocked transport — **no paid call in the suite**

### RF-031 — Bytes on the wire — `Transport.send_bytes`, `tts_audio`, `tts_end`

**Description:**
The wire seam. `Transport.send()` accepts only `str` today, so there is no path for a binary frame
at all. Touches `server/roboface_server/{router,app}.py`, `tests/fake_device.py`,
`specification/ARCHITECTURE.md`, and `tests/contract/`.

**What needs to be done:**
- Add `send_bytes(data: bytes)` to the `Transport` Protocol and implement it in
  `WebSocketTransport`. This is a **seam change** and carries its `ARCHITECTURE.md` update and
  contract test in the same commit.
- The router emits `tts_audio` as **binary frames with no envelope**, and closes the speaking window
  with a JSON `tts_end`. `protocol.py` already models this — `server_binary_meaning(SPEAKING)`
  returns `TTS_AUDIO` — so the router consumes that function rather than restating the rule.
- Track the connection's `BinaryPhase` so `SPEAKING` is true exactly while audio is being sent. A
  binary frame outside that window has no meaning, which is what makes the unlabelled framing safe.
- `fake_device` learns to receive binary frames and record their order relative to JSON ones — the
  interleaving assertion in RF-032 is impossible without it.
- A dropped socket mid-audio ends the turn the way any other disconnect does; audio is not special.

**Dependencies:** RF-029

**Expected result:**
The server can put PCM on the wire, framed as the protocol already says it should be.

**Acceptance criteria:**
- [ ] `Transport.send_bytes` exists on the Protocol and in `WebSocketTransport`
- [ ] `tts_audio` frames carry a raw payload with **no JSON envelope**; `tts_end` is JSON
- [ ] Binary frames are sent only while the phase is `SPEAKING`
- [ ] **Contract test:** the framing and the phase rule, driven by the fake device
- [ ] `specification/ARCHITECTURE.md` records the widened `Transport` seam, in this commit
- [ ] The fake device records binary and JSON frames in arrival order

### RF-032 — The orchestrator speaks while it writes

**Description:**
The join on the server: LLM deltas feed the splitter, completed phrases feed TTS, and chunks go out
while the model is still generating. Touches `server/roboface_server/orchestrator.py` and
`tests/integration/`.

**What needs to be done:**
- Feed each LLM delta to the `PhraseSplitter`; for every phrase it closes, synthesize and forward
  chunks **immediately** — never collect a turn's audio and send it at the end.
- A **first-audio budget** (~3 s) on the *first chunk of each phrase*, following the shape
  `DEFAULT_FIRST_TOKEN_BUDGET_S` already uses: awaited on the first output so a stalled vendor fails
  fast while a slow-but-flowing one is never cut off mid-phrase.
- A failure mid-phrase aborts the turn with the mapped error and rolls history back, using the
  existing `_abort_turn`. The turn invariant stays total — v0.2's review made it so, and a second
  provider must not reintroduce a third ending.
- `flush()` the splitter at the end of the reply so a short answer is still spoken.
- The reply deltas keep going out as they do today. Speech is added *alongside* the text, not
  instead of it.

**Dependencies:** RF-028, RF-030, RF-031

**Expected result:**
A turn in which audio for the first phrase leaves before the last word has been generated.

**Acceptance criteria:**
- [ ] Phrases are synthesized as they close, not at the end of the turn
- [ ] The first-audio budget is awaited on each phrase's first chunk only
- [ ] A TTS failure mid-turn aborts cleanly with `tts_failed` and rolls history back
- [ ] **Integration test:** `text_in → tts_end` against mocks, asserting the fake device saw
      **interleaved** `reply` and `tts_audio` frames — not one burst of text then one of audio
- [ ] Ties to the phase DoD: "speech starts before the model has finished generating"

### RF-033 — Firmware `audio_io` — streaming playback

**Description:**
The device half: play each `tts_audio` frame as it arrives. Touches `firmware/src/pure/` (the ring
buffer), `firmware/src/app/audio_io.*` (the hardware), `firmware/src/main.cpp` and
`firmware/test/`.

**What needs to be done:**
- **Pure:** a ring buffer that is **lossless** — it consumes exactly what plays and never truncates
  in a callback. Host-tested, Arduino-free, in `src/pure/`.
- **Underrun waits, it does not fill.** A starved buffer must not emit silence into the middle of a
  word: silence mid-phrase is worse than a pause, because it sounds like the sentence ended.
- **Glue:** the Core S3 shares one I2S bus between mic and speaker, so switch mic→speaker **once**,
  on the first chunk of a turn — not per frame — and drain then switch back on `tts_end`.
- Volume from `config.h`.
- Playback is cleanly interruptible by `restart` or an `error` frame, leaving the bus in a state the
  next turn can use.
- The device treats a binary frame as `tts_audio` only while it is speaking, mirroring
  `server_binary_meaning`; `firmware/src/pure/ws_protocol.h` already names the messages.

**Dependencies:** RF-031

**Expected result:**
PCM arriving over the socket comes out of the speaker as it arrives.

**Acceptance criteria:**
- [ ] The ring buffer is lossless — every byte written is played exactly once
- [ ] An underrun waits rather than emitting silence, and recovers when data arrives
- [ ] The bus switches mic→speaker once per turn, and back on `tts_end`
- [ ] Playback stops cleanly on `restart`/`error` and the next turn still works
- [ ] **Unit test:** the ring buffer's lossless and underrun behaviour, under `pio test -e native`
- [ ] `pio run -e cores3` compiles; no Arduino include reaches `src/pure/`

### RF-034 — Out loud — the hardware DoD and the docs

**Description:**
The DoD is a thing you hear, so this is the check on real hardware plus the documentation. Touches
`TESTING.md`, `DEPLOYMENT.md`, and `firmware/src/config.example.h` if volume was added there.

**What needs to be done:**
- Type a line over serial and **hear the answer** from the board's speaker.
- **Prove the streaming claim from the logs, not by feel:** the first `tts_audio` frame must be
  timestamped *before* the final `reply` delta. If it is not, the pipeline is accumulating somewhere
  and the phase has not met its goal however good it sounds.
- Confirm the first spoken phrase is not a half-word.
- Confirm a failed synthesis ends the turn cleanly and the device returns to `idle`.
- Document the check in `TESTING.md`, including that this is the first phase whose verification
  **costs money** — the suite stays mocked, but hearing it requires a real ElevenLabs call.

**Dependencies:** RF-032, RF-033

**Expected result:**
The phase DoD is demonstrated on hardware and written down so it can be repeated.

**Acceptance criteria:**
- [ ] A typed line is answered out loud from the board
- [ ] Log timestamps show the first `tts_audio` preceding the final `reply` delta
- [ ] The first spoken phrase is a whole word
- [ ] A failed or interrupted synthesis returns the device to `idle`
- [ ] `TESTING.md` documents the check and its cost

## v1.1 scope notes

**Total effort:** roughly 25–35 days across seven issues; one S, four M, two L.
**Critical path:** RF-029 → RF-031 → RF-033 → RF-034, with RF-032 joining before the DoD.
**Phase DoD (roadmap §v1.1):** a line typed over serial is answered **out loud**, and **speech starts
before the model has finished generating** (verified by log timestamps: first `tts_audio` precedes the
final `reply` delta); the first spoken phrase is never a half-word; an interrupted or failed synthesis
ends the turn cleanly and returns to `idle`.
**Contracts pinned this phase:** the **`TTSProvider` seam** (RF-029) and the widened **`Transport`
seam** — `send_bytes` (RF-031). Both carry their `ARCHITECTURE.md` update and contract test in the
same commit. The WS *vocabulary* is unchanged: `tts_audio`, `tts_end` and `tts_failed` were declared
in v0.1 and are already mirrored in the firmware.
**Model note:** chat runs on **Gemini 2.5 Flash only** (`thinkingBudget: 0`) behind the `LLMProvider`
seam; **no paid APIs** — every provider seam is mocked and a fake device drives the protocol for unit +
integration tests. TTS adds a second vendor behind its own seam; speech is not chat. RF-034's hardware
check is the one place a real ElevenLabs call happens, and it is a manual DoD step, never a test.
