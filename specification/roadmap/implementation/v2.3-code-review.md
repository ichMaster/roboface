## 1. 🟠 MEDIUM — the envelope freezes when the backlog runs dry

**Where:** `firmware/src/app/audio_io.cpp`, the drain loop — `output_level_` is updated **inside**
`while (!backlog_.empty() && …)`.

**Failure scenario:**

1. Mid-reply, the network falls behind. TTS chunks stop arriving for a second while the speaker
   plays out what it already has — the ordinary shape of a slow connection, and the reason the device
   buffers at all.
2. `backlog_` empties. The loop body does not run, so `followEnvelope` is not called.
3. **`output_level_` holds its last value** — not decays, holds. The mouth stays in whatever shape
   that level maps to, wide open if the stall landed on a stressed syllable, for as long as the stall
   lasts.
4. Chunks resume, and the mouth carries on as though nothing happened.

The envelope is a **level per chunk handed over**, when what it models is a level per unit of time.
Those coincide exactly as long as chunks keep arriving, which is why nothing has caught it: every
measurement so far has been of a reply flowing freely.

**Why this is the phase's characteristic bug.** Both of this ladder's previous failures were the same
shape — a signal that did not move. The peak detector did not move because it saturated; this does
not move because it is not asked. A mouth frozen open is the most visible failure this subsystem has,
and it has now been reported by the user twice from two different causes.

**Proposed fix.** Decay by elapsed time when no chunk was consumed. `tick` already takes `now_ms`;
one decay step per chunk-duration of silence keeps the units honest without adding a timer. The end
of a reply is already handled — `releaseBus()` zeroes the level — so this is specifically about
stalls *inside* one.

**Regression test.** In pure logic, where the rule belongs: an envelope stepped with no new samples
must fall, and must reach the closing threshold of the bottom rung within a stated time.

## 2. 🟠 MEDIUM — the fixture that taught the lesson still contains the mistake

**Where:** `firmware/test/test_envelope/test_envelope.cpp` — `tone()` generates a plain sine, and
`test_the_envelope_moves_over_a_speech_like_signal` calls the result speech-like.

**Failure scenario.** Not a crash — a test that means less than it says, which on this particular
subject is worse.

RF-066 established, on the board, that a sine carries roughly twice the energy of speech at the same
peak: crest factor 1.4 against 3–4. That is why `test_lipsync`'s fixture was rewritten, and why the
viseme ladder had to be recalibrated after being calibrated once already.

`test_envelope` was not rewritten. So the file whose header explains at length why fixtures must
model the signal is asserting a property "over a speech-like signal" using one that is not. Its
numeric bounds (`high > 0.4`) are tuned to the sine and would fail against real speech — which means
the test now encodes the wrong range as correct.

**Proposed fix.** Give `tone()` the same crest factor as `test_lipsync`'s `block()`, and re-derive the
bounds from what the board reports (0..0.38) rather than from the sine (0..0.67). The two files
deliberately keep separate generators — a fixture two tests share is one neither can change — so this
is a duplicated fix, and the duplication is the design.

**Regression test.** The change *is* the test: the assertion's bounds become the ones a real device
produces, so a future envelope change that no longer matches the board fails here.

## 3. 🟡 LOW — `speaking_mouth_` reads as dead code and is not

**Where:** `firmware/src/app/procedural_renderer.h` / `.cpp`. Carried from v2.2's review (finding 6),
deferred to "documentation, in the next pass over that file". This is that pass.

Since v2.2, `show(DeviceState)` is only called for device-owned states, so `speaking_mouth_` — set
from `state == kReplying` — looks unreachable. It is not: it is the path a server that sends **no**
`emotion{}` frames still takes. That is not hypothetical, as RF-063 discovered when the board turned
out to have been talking to a pre-v2.2 server on the LAN for the whole of that issue.

The risk is a future cleanup deleting it as dead. It wants a comment saying what it is.

## What's solid

- **The two-measure split is properly argued and properly separated.** `level.h` keeps its peak for
  the meter and now says which question it is answering; `envelope.h` measures energy for the mouth
  and says why the other argument does not transfer. Neither constant can drift into the other,
  because they are not the same constant.
- **The ladder's tests assert the property, not the numbers.** "Every rung is reached, none
  dominates" is what made RF-066's recalibration a change of constants rather than a change of
  design. The test was right; it was asked of the wrong signal, which is finding 2.
- **The frame rate was established rather than assumed.** Three intervals measured, not one — so
  "the interval is the binding constraint" is a result rather than a guess, and `drop=0 ref=0`
  through a thirty-second reply is a measurement rather than a hope.
- **`int64_t` in the accumulator, and the reasoning is in the comment.** 512 samples squared at full
  scale overflows 32 bits two hundred times over, and the passages that would wrap are the loudest
  ones.
