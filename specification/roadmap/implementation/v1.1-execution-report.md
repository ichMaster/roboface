## Detailed results

### RF-028 -- the PhraseSplitter
Boundary + **following whitespace** is the rule, and the whitespace is the point: it turns "is this
a sentence end?" from a guess into an observation, and gives "not yet" as an answer distinct from
"no" -- which is what stops `3.5` becoming two spoken phrases. 19 tests, fed character by character.

### RF-029 -- the TTSProvider seam
`synthesize(text) -> AsyncIterator[bytes]`, PCM16 16 kHz mono, not `async def`. The contract test
asserts the **streaming shape**, because an implementation that gathered a whole phrase before
yielding satisfies every type in the signature and defeats the phase.

### RF-030 -- ElevenLabs
`/stream` with `pcm_16000`. Realigns chunk boundaries to whole PCM16 samples: the transport splits
where it likes, and forwarding a chunk that ends mid-sample shifts everything after it by a byte.

### RF-031 -- bytes on the wire
`Transport.send()` took only `str`; the message types had existed since v0.1 and the transport had
not. A turn now emits `ReplyDelta | AudioChunk` because the two interleave. The speaking window
closes on **every** exit path.

### RF-032 -- the orchestrator
Deltas are yielded first, then fed to the splitter, so text never waits behind audio. The
first-audio budget sits on each phrase's first chunk.

### RF-033 / RF-034 -- the device
Four faults, all found on hardware, none reachable from a host test. They are listed in
`v1.1-code-review.md` under "What the hardware found", because each is a lesson about this stack
rather than a mistake in this phase alone.

## Architecture impact

Two seams widened, both documented in `ARCHITECTURE.md` in their own commits:

- **`TTSProvider`** -- the second vendor seam. Speech is not chat, and MISSION's Gemini-only rule is
  about chat.
- **`Transport.send_bytes`** -- and with it, `Responder` now yields `TurnEvent` rather than `str`.
  Anything later that emits from a turn adds a variant to that union rather than a second iterator.

Three device-level facts the next phase must build on:

1. **PSRAM reports zero free on this board.** `ESP.getFreePsram()` is 0 despite `qio_opi` and
   `-DBOARD_HAS_PSRAM`. Audio falls back to internal RAM. **v3's JPEG buffers assume PSRAM**, so this
   has to be resolved before then; raised as a review finding.
2. **`M5.Speaker.playRaw` drops a chunk when its slots are full** -- it does not wait. Any later
   audio path must be paced by its return value.
3. **`ws.cpp` whitelists which parse results reach the app.** A new `ParseResult` needs adding there
   as well as in the parser, or it is discarded silently one layer below `main.cpp`.
