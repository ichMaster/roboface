### RF-002: `protocol.py` -- the wire contract and its codec
**Status:** completed - **Commit:** `95f54ef` - **GitHub:** #2
**Validation:** [x] pytest 97 - [x] mypy strict - [x] ruff - [x] CI green - [x] contract test - [x] acceptance

The full vocabulary in both directions, `ErrorCode` (11), `Capability` (5), `PROTO_VERSION`, the
PCM16/16 kHz/mono constants, `hello` negotiation, and the no-envelope rule as a phase predicate.

Two layers of codec: `decode_envelope` round-trips **any** declared type, typed frames cover the
six v0.1 exchanges. `UnsupportedMessage` is deliberately distinct from `UnknownMessage` -- that
distinction is what lets the router answer a declared-but-unbuilt type with a clean error and
treat an invented one as a broken device, and it is the extension point every later phase uses.

**Architecture impact.** ARCHITECTURE §Contracts gained two wire details that existed only in code
and that the firmware must match from v0.3:
- `hello.audio_fmt` is spelled `format/rate/channels` -- **`pcm16/16000/1`** -- and `protocol.py`
  owns the constant the ASR/TTS adapters agree with.
- `hello.proto_ver` is **1**, with **no compatibility window**: any other version is rejected with
  `proto_unsupported` and the socket closes.

### RF-003: `router.py` -- the per-connection state machine and WS route
**Status:** completed - **Commit:** `404c087` - **GitHub:** #3
**Validation:** [x] pytest 122 - [x] mypy strict - [x] ruff - [x] CI green - [x] acceptance

`Connection`, `ConnectionPhase`, `ConnectionRegistry`, `Router.serve()`, plus `app.py` with the
`/ws` endpoint and the `WebSocketTransport` adapter.

The router is written against a small `Transport` protocol rather than FastAPI's `WebSocket`. That
is the load-bearing decision: it makes teardown checkable, because a scripted transport can raise
on demand where a real socket cannot. All three teardown paths are asserted.

`text_in` is answered through an injected `Responder` (v0.1: echo). **v0.2 replaces that injection
and nothing else in this module moves** -- no `LLMProvider`, no `providers/`, no streaming here.

### RF-004: Fake device harness and the `text_in -> reply` integration turn
**Status:** completed - **Commit:** `4ec922c` - **GitHub:** #4
**Validation:** [x] pytest 135 - [x] mypy strict - [x] ruff - [x] CI green - [x] acceptance

`tests/fake_device.py` encodes and decodes exclusively through `protocol.py`, so a contract change
breaks the harness loudly instead of letting the suite drift from the wire. `send_raw` is the one
sanctioned bypass. Its surface is *frames*: `send_binary` is already there for v1's PCM and v3's
JPEG, and `drain(count)` is what v0.2 will assert a delta stream with.

**It found a real defect on its first run.** `WebSocketTransport.close()` guarded on `client_state`,
but double-close is governed by `application_state`. The rejection path closes inside the router
*and* again in the endpoint's `finally`, so **every rejected `hello` raised** `RuntimeError: Cannot
call "send" once a close message has been sent`. Fixed in this commit. It could not surface in
RF-003's unit tests, which drive a scripted transport with no Starlette state machine to violate --
which is exactly the gap an integration harness exists to fill.

### RF-005: Structured logging keyed by `device_id` + `session_id`
**Status:** completed - **Commit:** `1ff82f4` - **GitHub:** #5
**Validation:** [x] pytest 159 - [x] mypy strict - [x] ruff - [x] CI green - [x] acceptance

Ids bound once per connection into a `ContextVar`; asyncio copies the context into each task, which
is the isolation two simultaneous devices need -- asserted with two sockets genuinely open at once.
The context is captured at `log()` time rather than at format time, so a deferred handler cannot
attribute a line to whoever came next.

Two enforced rules: the shape of a line never varies (pre-`hello` lines carry an explicit `null`
`device_id`), and bodies never appear (`chars(text)`, never `text`).

## Findings carried to review

1. **`ErrorCode` has no code for an unparseable inbound frame.** A malformed or unknown frame is
   currently reported as `internal`, which misattributes a device-side fault to the server. Adding a
   twelfth code would be a unilateral change to a contract the specification enumerates explicitly,
   so it was documented in `protocol.py`, tested as-is, and left for review to decide. This is the
   one open design question v0.1 produced.
2. **The product and `codegen/` share one local `.venv`.** Installing `pytest-asyncio` for the
   product added one `PytestDeprecationWarning` to `codegen/`'s run (it does not set
   `asyncio_default_fixture_loop_scope`). `codegen/` still passes 542/17 and was deliberately not
   edited -- it is imported infrastructure, outside this phase's scope, and CI installs the two
   suites separately. Local-environment note only.
