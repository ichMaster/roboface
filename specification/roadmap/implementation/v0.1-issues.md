# v0.1 — GitHub Issues

Issues for phase **v0.1 — Server skeleton and the wire contract** (version **v0 — Skeleton**),
derived from the per-phase Tasks in [ROADMAP.md](../../ROADMAP.md) (§v0.1) and the
contracts in [ARCHITECTURE.md](../../ARCHITECTURE.md) (§Components, §Contracts → WS device↔server,
§Error codes, §Configuration and secrets, §Stack and repository layout, §Testing and CI).
This file is scoped to a single phase; IDs continue from the previous phase
(RF-— → **RF-001…RF-005**) — this is the first phase, so the sequence starts here.

v0.1 stands the server up and pins the wire before anything is built on it: a pure `protocol`
module that owns the message set, the `ErrorCode` enum, the JSON codec and `hello` negotiation; a
`router` that is one connection state machine per device; and the **fake device** every later phase's
test suite drives the protocol with. There is no model call yet — `text_in` echoes through a mock
responder, and v0.2 replaces that responder with the `LLMProvider` seam and the orchestrator. Doing
the contract first is what lets v0.2–v3 extend the protocol instead of renegotiating it.

## v0.1 — Server skeleton and the wire contract

### RF-001 — Repo scaffold: pyproject, server package, config, CI

**Description:**
Create the project's Python skeleton so every later issue has a place to put code and a command that
proves it. Touches the repo root (`pyproject.toml`, `.github/workflows/ci.yml`), `server/` (the
package and its config loader) and `tests/`. `codegen/` keeps its own `pyproject.toml` and is
unaffected — the root config must not sweep it into the product's test run.

**What needs to be done:**
- Root `pyproject.toml`: `[tool.pytest.ini_options]` with `pythonpath = ["server"]` and
  `testpaths = ["tests"]` (so `pytest` from the root collects the product suite and **not**
  `codegen/tests`); `[tool.ruff]` line-length 100, target `py311`, lint select `["E","F","I","UP","B","SIM"]`;
  `[tool.mypy]` `strict = true` scoped to the server package. No `[project]` table is required.
- `server/roboface_server/__init__.py` — the package root that `pythonpath = ["server"]` exposes as
  `roboface_server` (the shape ARCHITECTURE §Stack and repository layout assumes, mirroring Pyramid's
  `server/pyramid_server/`).
- `server/roboface_server/config.py`: load `server/.env` (python-dotenv, absent file tolerated) and
  expose the **three variables ARCHITECTURE §Configuration marks as v0.1** — `ROBOFACE_WS_HOST`
  (default `0.0.0.0`), `ROBOFACE_WS_PORT` (default `8000`), `ROBOFACE_LOG_LEVEL` (default `info`).
  A typed, frozen settings object; no other variable is read this phase.
- Verify `server/.env.example` against the ARCHITECTURE §Configuration table — it is **already
  committed** and already carries every key; correct it only if it disagrees with the table. Do not
  regenerate it and never commit `server/.env`.
- `tests/` with `__init__.py`-free layout and a `conftest.py` placeholder for the fixtures RF-004 adds.
- `.github/workflows/ci.yml`: on push and PR, install the dependencies, run `ruff check server tests`,
  `mypy server`, and `pytest`. The product suite only — `codegen/` is tested from inside its own
  directory and must not be collected here.
- Pin the runtime dependencies the phase actually needs: `fastapi`, `uvicorn`, `websockets`,
  `python-dotenv`; dev: `pytest`, `pytest-asyncio`, `ruff`, `mypy`, `httpx`.

**Dependencies:** None

**Expected result:**
`ruff check server tests`, `mypy server` and `pytest` all run clean from the repo root, CI runs the
same three on every push, and `codegen/`'s 542-test suite is untouched by either.

**Acceptance criteria:**
- [ ] `pytest` from the repo root collects **only** `tests/` — a test asserts `codegen/tests` is not
      swept in (this is a documented foot-gun: `codegen/pyproject.toml` exists precisely to avoid it).
- [ ] `mypy server` passes under `strict = true`; `ruff check server tests` is clean.
- [ ] **Unit test:** `config.py` defaults apply when the variable is absent, an explicit env value
      overrides them, and a missing `server/.env` is not an error.
- [ ] CI is green on the branch and runs ruff + mypy + pytest (ties to the v0.1 DoD "ruff and pytest
      are green in CI").

### RF-002 — `protocol.py` — the wire contract and its codec

**Description:**
The **first of the five seams** (ARCHITECTURE §Providers and seams): a pure, dependency-free
`server/roboface_server/protocol.py` that owns the entire device↔server message set, the error-code
enum, the JSON text-frame codec and `hello` negotiation. Pure means importable with no FastAPI, no
websockets and no I/O — it is the module the contract test pins and the firmware's `ws_protocol.h`
mirrors from v0.3.

**What needs to be done:**
- **Message-type constants, both directions**, exactly as ARCHITECTURE §Contracts → WS device↔server
  lists them. device→server: `hello`, `listen_start`, `listen_stop`, `text_in`, `event`, `image_in`,
  `ping`. server→device: `asr_partial`, `asr`, `reply`, `emotion`, `tts_audio`, `tts_end`,
  `config_updated`, `error`, `restart`, `pong`. Declare the **whole** set now even though v0.1 only
  exercises `hello`/`text_in`/`reply`/`error`/`ping`/`pong` — the contract is the deliverable, not
  the subset in use.
- `ErrorCode` as a `StrEnum` with the eleven enumerated values and nothing else: `wifi_lost`,
  `server_unreachable`, `proto_unsupported`, `unauthorized`, `rate_limited`, `asr_failed`,
  `llm_timeout`, `llm_failed`, `tts_failed`, `vision_failed`, `internal`.
- The **text-frame codec**: `encode(msg) -> str` and `decode(raw) -> Message`, with typed frame
  objects (dataclasses or `TypedDict`) per message. Decoding rejects, with a distinct exception
  carrying an `ErrorCode` hint: non-JSON, a non-object top level, a missing/unknown `type`, and a
  frame whose required fields are absent or the wrong type.
- **`hello` negotiation**: parse `hello{device_id, proto_ver, audio_fmt, caps}`; a pure
  `negotiate(hello) -> Accepted | Rejected(ErrorCode.proto_unsupported)` that compares against a
  `PROTO_VERSION` constant this module owns. `caps` is a set over `touch`, `camera`, `dual_mic`,
  `halo`, `buttons` (ARCHITECTURE §Hardware variants); unknown caps are ignored, not rejected.
- **Audio constants**: `AUDIO_SAMPLE_RATE = 16000`, `AUDIO_CHANNELS = 1`, `AUDIO_FORMAT = "pcm16"`,
  and the `audio_fmt` string the device sends — the single place these live, since ARCHITECTURE notes
  the format is fixed in three places at once and they must agree.
- **Binary frames carry raw payloads with no envelope** — encode that as an explicit rule in the
  module (a documented predicate on direction + connection state), not as an implicit convention.

**Dependencies:** RF-001

**Expected result:**
A pure module that round-trips every text frame, rejects malformed input with an enumerated code, and
answers `hello` with an accept or `proto_unsupported` — importable with no framework present.

**Acceptance criteria:**
- [ ] **Contract test** (`tests/contract/test_ws_protocol.py`) pins the seam: the full inbound and
      outbound message-type sets, the eleven-value `ErrorCode` enum, the `PROTO_VERSION` constant, the
      audio constants, and `hello` negotiation. This file changes **only when the contract changes** —
      and if any detail here is found to differ from ARCHITECTURE §Contracts, the ARCHITECTURE update
      lands in **this same issue**, per the seam rule.
- [ ] **Unit test:** codec round-trip over every text frame; malformed-frame rejection for non-JSON,
      non-object, missing `type`, unknown `type`, and wrong-typed required fields.
- [ ] **Unit test:** `negotiate` accepts the current `PROTO_VERSION` and rejects any other with
      `ErrorCode.proto_unsupported`; unknown `caps` entries are ignored.
- [ ] A test asserts the module imports with **no** `fastapi`/`websockets` import in its module graph
      (purity is the property that makes it the firmware's mirror).

### RF-003 — `router.py` — the per-connection state machine and WS route

**Description:**
`server/roboface_server/router.py` plus the FastAPI application that mounts it: accept a WSS
connection, negotiate `hello`, hold **one state machine per device**, dispatch decoded frames, answer
`ping` with `pong`, and tear the connection down cleanly in a `finally` block. `text_in` is answered
through an **injected responder** whose v0.1 implementation echoes — v0.2 replaces that injection
point with the orchestrator and the `LLMProvider` seam, and nothing else about this module changes.

**What needs to be done:**
- `server/roboface_server/app.py`: the FastAPI app with a `/ws` websocket endpoint bound to
  `ROBOFACE_WS_HOST`/`ROBOFACE_WS_PORT` from RF-001's config; a `uvicorn` entrypoint.
- `router.py`: per-connection state — `device_id`, `session_id` (generated per connection), the
  negotiated `caps`, and the connection phase (`awaiting_hello → ready → closing`). A frame arriving
  before `hello` is a protocol error, not a crash.
- **Negotiation**: the first frame must be `hello`; on `Rejected`, send `error{code:
  proto_unsupported, msg}` and close — the device is never left connected to a server that cannot
  speak to it.
- **Dispatch** over the decoded frame type; every message type the protocol declares but this phase
  does not implement returns a clean, enumerated `error` rather than an unhandled exception.
- `ping` → `pong`, both directions tolerated.
- `text_in` → the injected `Responder` protocol (`async def respond(text: str) -> str` for now) →
  `reply{text, final: true}`. The v0.1 implementation is a mock echo responder; **do not** add an
  `LLMProvider` seam, a provider package, or streaming here — that is v0.2's scope by design.
- **Clean teardown in a `finally` block**: the connection is removed from the registry and the state
  discarded whether the socket closed normally, errored, or the client vanished.

**Dependencies:** RF-002

**Expected result:**
A websocket endpoint that a client can connect to, greet, ping and send `text_in` to, receiving a
`reply` — and that rejects a bad `proto_ver` with `proto_unsupported` before anything else happens.

**Acceptance criteria:**
- [ ] **Unit test:** the connection state machine — a frame before `hello` is rejected; a second
      `hello` on a `ready` connection is rejected; teardown runs on normal close, on an exception, and
      on an abrupt disconnect (assert the registry is empty in all three).
- [ ] **Unit test:** dispatch maps each declared-but-unimplemented message type to an enumerated
      `error`, with **no** unhandled exception escaping the handler.
- [ ] `ping` is answered with `pong`; `text_in` is answered with `reply{text, final: true}` through
      the injected responder, with the **LLM mocked by default** (the echo responder is the mock —
      no network call exists in this phase).
- [ ] An unsupported `proto_ver` yields `error{code: proto_unsupported}` and a closed socket (ties
      directly to the v0.1 DoD).

### RF-004 — Fake device harness and the `text_in → reply` integration turn

**Description:**
The **fake device** every later phase depends on (ARCHITECTURE §Testing and CI: "a fake device speaks
the WS protocol in tests"). A reusable async test client in `tests/` that connects to the app, sends
`hello`, and exchanges frames — plus the integration test that drives the v0.1 DoD end to end. This
harness is a long-lived asset: v1 will push binary PCM through it, v3 JPEG frames, so its API is
designed for frames in general, not for `text_in` alone.

**What needs to be done:**
- `tests/fake_device.py`: an async context-managed client over the FastAPI test transport —
  `connect()`, `hello(device_id, proto_ver, audio_fmt, caps)`, `send(frame)`, `send_binary(payload)`,
  `recv()` / `recv_until(type, timeout)`, `close()`. It encodes and decodes through
  `protocol.py` itself, so a contract change breaks the harness loudly instead of letting tests drift
  from the wire.
- Register it as a pytest fixture in `tests/conftest.py`, with `pytest-asyncio` configured.
- **Integration test — the happy path:** connect → `hello` → `text_in{text}` → assert a
  `reply{text, final: true}` comes back from the mock echo responder.
- **Integration test — the rejection path:** `hello` with an unsupported `proto_ver` → assert
  `error{code: proto_unsupported}` and that the socket is then closed.
- **Integration test — liveness and teardown:** `ping` → `pong`; and after the client disconnects,
  the server's connection registry is empty.
- Keep the harness free of any product-code import beyond `protocol.py` and the app factory, so it
  cannot quietly become a second implementation of the router.

**Dependencies:** RF-003

**Expected result:**
`pytest` proves the whole v0.1 DoD from the outside — a fake device connects, negotiates, converses
and is rejected when it speaks the wrong protocol version — with no hardware and no paid API.

**Acceptance criteria:**
- [ ] **Integration test:** the fake device connects, negotiates `hello`, sends `text_in` and
      receives `reply` — the v0.1 DoD's first clause, asserted rather than described.
- [ ] **Integration test:** an unsupported `proto_ver` is rejected with `proto_unsupported` — the
      DoD's second clause.
- [ ] The harness encodes/decodes exclusively through `protocol.py` (a test or review note pins this),
      so it stays a client of the seam and not a copy of it.
- [ ] **No paid API call and no hardware** anywhere in the suite; the responder is the mock echo.

### RF-005 — Structured logging keyed by `device_id` + `session_id`

**Description:**
Every log line a connection produces must say **which device and which session** it came from —
without that, the multi-device, multi-turn logs of v1+ are unreadable. Adds
`server/roboface_server/logging.py` and threads its context through the router's connection lifetime.
Reads `ROBOFACE_LOG_LEVEL` from RF-001's config.

**What needs to be done:**
- A structured logger emitting one JSON object per line: timestamp, level, event name, `device_id`,
  `session_id`, plus per-event fields. Level from `ROBOFACE_LOG_LEVEL`.
- Bind the context **once per connection** (a `contextvars`-based binding, so a coroutine inherits it
  without every call site passing the ids by hand) and log the lifecycle: connection accepted, hello
  negotiated (with `proto_ver` and `caps`), each dispatched frame type, each `error` with its
  enumerated code, and teardown with the reason.
- Before `hello` completes there is no `device_id` — log those lines with the field explicitly null
  rather than omitting it, so the shape of a line never varies.
- **Never log a secret or a payload body**: no `.env` value, no full `text_in`/`reply` text (log a
  length instead). This is the rule that keeps the log safe to paste into an issue.

**Dependencies:** RF-003

**Expected result:**
Every server log line is a JSON object carrying `device_id` and `session_id`, from connection accept
through teardown, at the configured level.

**Acceptance criteria:**
- [ ] **Unit test:** a bound context produces `device_id` and `session_id` on every line emitted
      inside it, and lines emitted before `hello` carry an explicit null `device_id`.
- [ ] **Unit test:** `ROBOFACE_LOG_LEVEL` gates output — a `debug` line is suppressed at `info`.
- [ ] **Unit test:** the redaction rule — a `text_in` body never appears in a log line; its length
      does.
- [ ] Two concurrent fake-device connections produce lines with **distinct** `session_id`s and no
      cross-contamination (the property `contextvars` is there to guarantee).

## v0.1 scope notes

**Total effort:** ~13 points (S=1, M=3, L=5) — roughly 2 developer-weeks; the protocol module is over
a third of it and is deliberately the largest single piece in the phase.
**Critical path:** RF-001 → RF-002 → RF-003 → RF-004. RF-005 branches off RF-003 in parallel with RF-004.
**Phase DoD (roadmap §v0.1):** the fake device connects, negotiates `hello`, sends `text_in` and
receives a `reply`; an unsupported `proto_ver` is rejected with `proto_unsupported`; ruff and pytest
are green in CI.
**Contracts pinned this phase:** the **WS protocol** seam — `protocol.py` (message set both
directions, the `ErrorCode` enum, `PROTO_VERSION` and `hello` negotiation, the PCM16/16 kHz/mono
constants, the no-envelope rule for binary frames) — pinned by `tests/contract/test_ws_protocol.py`.
The other four seams (`EmotionFrame`, the provider seams, `IFaceRenderer` + skin manifest, the `caps`
flags) are declared in ARCHITECTURE but land in later phases; `caps` is parsed here and enforced from v6.
**Explicitly out of scope, by design:** no `LLMProvider` seam, no `providers/` package, no streaming
and no model call — `text_in` echoes through a mock responder and **v0.2** replaces that injection
point. No firmware (v0.3), no face (v0.4), no persistence (v4).
**Model note:** chat runs on **Gemini 2.5 Flash only** (`thinkingBudget: 0`) behind the `LLMProvider`
seam — introduced in v0.2, not here; **no paid APIs** — every provider seam is mocked and a fake device
drives the protocol for unit + integration tests.
